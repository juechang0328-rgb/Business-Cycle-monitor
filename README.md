# Business Cycle Monitor

以**日頻、免費、免 API key** 的市場資料，定位景氣循環六階段。

## 快速開始

```bash
pip install -r requirements.txt
python run.py                    # 輸出當前階段
python run.py --history 12       # 加上最近 12 個月軌跡
python run.py --csv out.csv      # 匯出完整時間序列
```

輸出範例：

```
==============================================================
  景氣循環定位   資料日期 2026-09-18
==============================================================
  階段4 景氣擴張（債↓ 股↑ 原物料↑）

  成長分數 G = +1.17   3個月動能 dG = +0.28
  通膨分數 I = +1.16   3個月動能 dI = -0.22

    銅金比                 +0.87  |               ████           |  (權重 22%)
    循環股/防禦股          +1.04  |               █████          |  (權重 18%)
    ...
```

## 核心邏輯

六階段由兩個軸決定 —— **成長軸 G** 決定股票，**通膨軸 I** 決定債券與原物料：

| 階段 | 名稱 | 債券 | 股票 | 原物料 | 判定條件 |
|---|---|:--:|:--:|:--:|---|
| 1 | 景氣衰退 | ↑ | ↓ | ↓ | G<0、動能<0、通膨已落 |
| 2 | 景氣谷底 | ↑ | ↑ | ↓ | G<0 但**動能轉正** |
| 3 | 景氣復甦 | ↑ | ↑ | ↑ | G≥0 上升、通膨仍低 |
| 4 | 景氣擴張 | ↓ | ↑ | ↑ | G≥0 上升、通膨已起 |
| 5 | 景氣高峰 | ↓ | ↓ | ↑ | G 高但**動能轉負** |
| 6 | 景氣趨緩 | ↓ | ↓ | ↓ | G<0 下降、通膨仍高 |

兩個分界值得記住：

- **階段 4 vs 5** 的差別不是經濟好不好（兩段都好），而是**成長率還在不在加速** → 所以要看二階動能
- **階段 6 vs 1** 的差別是**通膨是否已落** → 那決定債券箭頭何時翻正

換檔需連續 10 個交易日成立（遲滯），避免在 0 附近來回跳動。

## 資料源

| 來源 | 內容 | 是否需 key |
|---|---|---|
| yfinance | 標普500、黃金/銅/原油期貨、類股與債券 ETF、VIX、美元 | 否 |
| FRED CSV | 2/5/10 年期殖利率、10Y-2Y、10Y-3M、實質利率、通膨預期、HY OAS | 否 |

Yahoo **沒有 2 年期殖利率**，且 `^TNX` 歷史報價單位不一致，所以利率一律走 FRED。
詳見 [`docs/02-日頻資料源與ticker對照.md`](docs/02-日頻資料源與ticker對照.md)。

## 專案結構

```
bcm/
  sources.py      資料抓取（yfinance + FRED，含重試與單位正規化）
  indicators.py   指標設定：ticker、軸別、權重  ← 要調整就改這裡
  scoring.py      動能 → z-score → 加權合成（純函數）
  stages.py       六階段判定與遲滯（純函數）
run.py            CLI
tests/            14 項邏輯測試，含合成完整循環的端到端驗證
```

## 限制

- 市場資料是**對景氣的預期**，不是景氣本身 —— 反應快，但會有假訊號（例如純流動性驅動的反彈）。
  要提高可靠度，需加入月頻實體指標（ISM、建照、初領失業金），清單在 `config/indicators.yml`。
- 權重是先驗設定，**未經回測最佳化**。
