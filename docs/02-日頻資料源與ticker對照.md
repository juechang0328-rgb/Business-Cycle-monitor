# 日頻資料源與 ticker 對照

## 結論：yfinance 可以，但殖利率建議走 FRED

**yfinance 拿價格沒問題**（標普500、黃金、銅、原油、各類 ETF）。
但**殖利率**有三個坑，所以本專案採「yfinance 抓價格 + FRED 抓利率」的混合架構。
兩者都免費、免 API key、一行就能抓，複雜度沒有增加。

### 坑 1：Yahoo 沒有 2 年期殖利率

Yahoo 的 CBOE 殖利率指數只有這四檔：

| Ticker | 內容 |
|---|---|
| `^IRX` | 13 週國庫券 |
| `^FVX` | **5 年期** |
| `^TNX` | **10 年期** |
| `^TYX` | 30 年期 |

**沒有 2 年期。** 替代方案是 `2YY=F`（CBOT 2 年期殖利率期貨），
但它 2021 年才上市、歷史短且偶有跳空；`ZT=F` 則是 2 年期公債**期貨價格**不是殖利率，
不能直接拿來用。

→ **建議直接用 FRED 的 `DGS2`**，日頻、回溯到 1976 年、乾淨。

### 坑 2：`^TNX` 的報價單位在歷史上不一致

Yahoo 的殖利率指數曾以「殖利率 × 10」報價（`42.50` 代表 `4.25%`），
不同期間、不同 API 路徑回傳的刻度未必一致。抓長期歷史做 z-score 時，
中間若有刻度切換會直接把統計量毀掉。

本專案在 `bcm/sources.py` 放了 `normalize_yahoo_yield()` 做健全性檢查
（中位數 > 20 就除以 10），但若改用 FRED 就完全不必處理這件事。

### 坑 3：Yahoo 沒有利差與實質利率

`10Y-2Y`、`10Y-3M`、高收益債 OAS、TIPS 實質利率、損益兩平通膨率 ——
這些是判斷階段最關鍵的幾個序列，Yahoo 都沒有，FRED 全部都有而且是日頻。

## FRED 免 API key 的抓法

不需要註冊，直接打公開 CSV 端點：

```
https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS2
```

回傳兩欄 CSV（日期、數值，缺值為 `.`）。`bcm/sources.py` 的 `fetch_fred()` 已封裝好。

> 註：若要做嚴謹回測，需要「當時看到的版本」而非修正後的終值，
> 那才需要 ALFRED 與 API key。做即時監測不需要。

## 注意事項

1. **期貨合約轉倉**：`GC=F`、`HG=F`、`CL=F` 是連續合約，Yahoo 在轉倉時會有價格跳空。
   本專案用 3 個月變動率再取 z-score，影響有限；若要更嚴謹可改用對應 ETF（`GLD`、`CPER`、`USO`）。
2. **ETF 歷史長度**：`SOXX`(2001)、`HYG`(2007)、`TIP`(2003)、`DBC`(2006) —
   起始日設在 2008 以後比較不會有大片缺值。程式的加權合成會自動忽略尚無資料的成分。
3. **Yahoo 偶發限流**：`fetch_yahoo()` 已內建退避重試；若頻繁失敗可改抓一次存檔，不要每分鐘打。
4. **非交易日**：面板統一 reindex 到營業日並向前填補，FRED 的假日缺值也一併處理。
